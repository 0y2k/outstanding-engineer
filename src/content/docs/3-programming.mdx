## Haskell

トップバッターをHaskellにする時点でこの記事が目指す場所を察知するだけの能力が読者には求められているのかもしれません．
最近は環境を整えるのも容易になりました．ただしこれはモダンな言語は大抵そうなのでこれ単体では理由にはなりません．

Haskellは数学のように定義するだけでプログラミングが可能です．
左辺に名前，右辺に定義の記述，この2つを記号`=`で結ぶだけです．
名前`main`さえ定義してやると，あとはコンパイラが勝手に実行まで考えてくれます．
普通の言語とは異なり，定義と機械語が必ずしも対応している必要はありません．コンパイラが全部考えてくれます．
なので数学的な関数のような，単体では機械語を生成できないようなオブジェクトも名前を付けて取り回せます．
このシステムを強力に後押ししてくれるのが，悪名高い型システムです．

トップバッターにHaskellを選んだ理由は，数学の方法論がそのまま輸入できるからです．
左辺と右辺を記号`=`で結ぶなんてまさに数学ではないですか．
細かいことはコンパイラに任せて，人間は楽しましょう．

## Rust

プログラミングの学習はアルゴリズムを実装するようになってからが本番です．
アルゴリズムは大抵，数学では記述されていません．
コンピュータが持つメモリを前提とした手続きとして記述されていることが多いです．

手続き型としてオススメするのが，メモリを所有権によって厳格に管理できるRust言語です．

所有権については難しいと評判ですが，間違ったコードを書けばコンパイラが怒って知らせてくれます．怒ってはいませんが．
それさえ乗り越えてしまえば，速い，ネイティブバイナリを吐いてくれる，wgpuがゲーム作成にも昨今流行りのAIにも有効，などなど．
数多くのメリットを享受できる良い言語だと思う次第です．

こんなマイナー言語がお嫌ならこのRustだけPythonにでもすれば良いと思います．
開発が迷走してたりもしますがエコシステムなんかは揃っています．流石に人が多い言語は違いますね．

## Nix

プログラミング言語か？と改めて問われるとそうではないかもしれないです．
しかしASTに分解できて（できるよな？？）何かしらの実装を論理的に記述しているのできっとプログラミング言語でしょう．
ここで指した何かしらの実装はNixOSというLinux distributionの全体設定だったりします．つまり設定記述言語とも言えます．

OS何使ってます？窓？林檎？筆者としては両方ゴミにしか映りません．
その他Linux distributionもロールバック機能が存在しないという1点が引越しを促す理由にすらなります．
設定の書き換えが世代を構成し，例えば起動に失敗したならばロールバックによって世代を戻せばよろしい．
他にも大抵のパッケージが最新に保たれていたり，至れり尽くせりです．
そんな筆者オススメのNixOSで採用されているのがNix言語です．

欠点はコンパイラが吐くエラーメッセージが人間に易しくはないという点でしょうか．
OSのロールバック機能の前には霞む欠点です．
